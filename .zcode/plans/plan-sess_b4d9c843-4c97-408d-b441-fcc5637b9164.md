Two changes: reduce the Event Planning modal to a simple package picker, and remove the size selector from the product dialog.

## 1. Event Planning modal → package picker only (`src/components/CateringModal.tsx`)
The modal currently has 5 steps (Choose Experience → Select Drinks → Toppings → Bakery → Event Details/Quote form) plus a live-estimate bar and localStorage persistence. Per your screenshot, only the package selection stays:

- **Keep**: modal header/close, Step 1 "Choose Your Experience" with the 3 package cards (The Drop-Off 10–25 people, The MiTea Bar 25–75, The Whole Thing 75+) — adding the prices from your screenshot: **$180 / $350 / $520** on the respective cards.
- **Remove**: the cups/jugs format switcher + bulk-discount banner, Step 2 (drinks & quantities), Step 3 (toppings), Step 4 (bakery platters), the Live Catering Estimate / "Add Directly to Cart" / "Fill Event Details" bar, Step 5 (event details + quote request form), and the submitted-success screen — along with all the now-dead state, handlers, and localStorage builder logic (~1,000 lines deleted; file drops to roughly a simple picker).
- **New single CTA**: "Add to Cart • $<price>" (disabled until a package is selected) — adds the package to the cart via the existing `addToCart` (`size: "Catering Package"`, `sugar/ice: ""`, `toppings: []`, price = package price), closes the modal, opens the cart drawer with a toast. The customer's name/phone/email are collected at normal checkout, so no contact section is needed.
- Homepage catering cards and the "Plan Event" button keep working unchanged (they open this modal).

## 2. Remove size selector from the product dialog (`src/components/ProductModal.tsx`)
- Delete the "Choose Size" section, `selectedSize` state, and the `useCustomizations` presets usage — `unitPrice` becomes just `product.price`.
- The dialog becomes: image + name, description, **Special Instructions** textbox (kept as-is), quantity stepper, "Add to Cart" button.
- `handleAdd` sends `size: "Standard"`, `sizePrice: 0` (keeps the `CartItem` shape and backend validator happy; server-side price recalc treats it as $0 size surcharge — consistent).
